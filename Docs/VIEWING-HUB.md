# 观影空间

首页、观影、设置组成主导航。Bangumi 章节管理、完整片单、个人主页和 MoviePilot 搜索、订阅、下载管理从观影空间进入。媒体库搜索、Bangumi 搜索与 MoviePilot 搜索共用原生搜索框和关键词，首次直接搜索默认检索媒体库。各服务的启用开关、登录状态与失败提示独立处理。

## 数据来源

| 内容 | 来源与含义 |
| --- | --- |
| 待看、在看、看过 | Bangumi 收藏与逐集进度，不能代替实际观看记录 |
| 订阅、缺集、下载 | MoviePilot 资源获取状态，不能代替已看状态 |
| 继续观看 | Jellyfin / Emby 用户播放进度 |
| 服务器观看记录 | Jellyfin / Emby 已看电影和分集的 LastPlayedDate 最新快照；服务端可汇总其他播放器上报的记录 |
| App 实播 | OcPlayer 内实际经过的播放时间，未看完也记录；暂停、缓冲、跳转及长时间没有播放位置推进的区间不计时 |
| 番剧放送 | Bangumi 日历与 bangumi-data 放送周期、完结时间，交集限定为 Bangumi 在看、媒体库已有且仍在更新的作品 |

服务器快照每个条目只有最近一次已看日期，并非逐次播放日志。首次导入最近 30 个本地日历日，后续固定导入起点；按 DatePlayed 降序完整读取到起点，再原子提交。未完成扫描、失败、取消与迟到响应不能覆盖上一次档案。缺日期不编造记录，缺片长不编造小时；服务器时长按片长估算，远端取消已看后会在完整同步中移除对应快照。

App 实播按会话和本地日期累积，每 15 秒及暂停、退出等节点写入账号隔离档案。倍速按实际时间累计，跨午夜拆分；同一会话重复或迟到检查点采用累计值更新，避免重复计时。统计合并同来源、同条目、同日期的会话，并优先采用 App 实播代替服务器片长估算；电影与集数仍依据服务器已看状态。档案属于观看历史，只统计存储占用，不参与普通缓存的定期清理。

各数据源按账号、服务器、会话代次校验响应；切服、换号或登出立即隐藏旧快照。观影页可见且 App 活跃时每 60 秒同步观看记录，每 15 秒刷新下载进度。每日、本月、15 周活跃度、TOP3、类型分布与近 7 天趋势由上述记录计算，多类型条目的时长均分到各标签。

## 放送时间与媒体库确认

公开时间轴来自 [bangumi-data](https://github.com/bangumi-data/bangumi-data)，缓存 6 小时，离线保留上次成功数据。公开下载不带媒体服务器凭据。UTC 放送周期换算为本地日期和时间，按更新时间排序；缺失时间显示「更新时间待定」。媒体库确认优先采用已有 Bangumi 绑定或外部 ID；TMDB 后续季需对应季实际存在，标题回退保持季、篇章信息，不靠去掉季名合并不同作品。

## 头像、封面与布局

账号头像先判断 Jellyfin / Emby 自定义头像标记，没有自定义头像时采用 Bangumi 头像。来源选择与位图准备在根层提前进行，整个页头首次显示时已选好头像；换号后旧头像立即隐藏。

最近观看、完整历史和继续观看共用封面组件：分集优先使用剧集封面，缺图共用灰白影片图标，鉴权及缓存按当前服务器账号隔离。完整片单采用自适应海报卡，保留分类数量、原名、年份、话数、评分与评论；每页 20 条，滚动至末尾加载下一页，分类切换隔离旧请求并回到顶部。

卡片沿用原生 Liquid Glass。手机紧凑排布，宽屏重排为组合布局，辅助功能字号使用单列。导航、按钮、选中项、进度和趋势线保持灰白；类型分布图例保留品牌色，先前单独确认的活跃度与月度图表颜色沿用原方案。
