# 背景图与模糊层规划

2026-11-04 起按此文档维护图片来源、加载和显示生命周期。页面覆盖清单与采样工具见 [AMBIENCE.md](AMBIENCE.md)。

## 1. 页面拥有背景，视觉层只处理像素

| 场景 | 图片拥有者 | 合成入口 | 规则 |
| --- | --- | --- | --- |
| 首页 | `AppModel` 氛围池 | `AmbientBackdropCarousel` | 池内小图预热后轮播，整组模糊背景交叉淡入 |
| 普通路由与设置 | 氛围池 | `pageAmbience` / `routeAmbience` | macOS 透明页面借根层；iOS 在页面内补底 |
| 详情页（全部设备与版式） | `DetailViewModel.backdropArtwork` | `DetailBackdropView` | 固定进页快照，条目像素就绪后整组切换 |
| 资源搜索 / 下载管理 | 各自页面声明 | `pageAmbience` | 保留主体图及现有池兜底策略 |
| 播放器 | 播放画面 | 播放器渲染器 | 无氛围池背景 |
| sheet / 菜单 | 系统材质 | 系统呈现 | 不再加全页剧照或额外背景模糊 |

详情页在 macOS 和 iOS 都直接拥有页面内的底图，并用 `pageAmbience(nil)` 清除前一个页面的窗口图声明。`routeAmbience(.detail)` 直通，禁止再挂一张池图。导航栏、底栏可透出页面背景；图片不可越过当前详情视口去盖侧栏，也不参与命中测试或无障碍阅读。

## 2. 详情页只允许一个可见来源序列

1. **进入**：`attach` 只捕获一次当前氛围池 URL、认证头和内存中的 512 像素图片。持有实际像素，池轮播或缓存淘汰不改变它。未缓存时使用页面底色，不额外请求另一张过渡图。
2. **解析来源**：先读取本地 TMDB overlay，再接受详情数据；共用 `DetailBackdropSource` 的来源与认证策略。服务端/TMDB 优先级沿用用户偏好。合集自身无图时取首个带背景图的成员。首次非空来源在本次详情模型中锁定；晚到数据只补尚未锁定的来源。
3. **加载条目图**：只请求 1600 宽 URL、最多 1920 像素解码的一份图片。清晰层、模糊层不分别请求，不再把 URL 就绪视为像素就绪。重复调用共享进行中的加载。
4. **提交**：成功解码后一次性提交 `Snapshot(target, image)`。整个条目图组在 0.35 秒内淡入；过渡图位于下层。降低动态效果时直接切换。
5. **失败或无图**：保持固定进页快照或页面底色，保持头部和海报槽位的尺寸。其他作品的池图只可模糊展示，不能作为清晰英雄图。
6. **退出 / 返回**：退出取消未完成加载。取消后迟到的结果无法提交；返回同一模型可重新准备未完成的图片。返回首页由首页原有轮播接管；进入另一详情由新模型重新捕获快照。

来源锁定和图片就绪是两个阶段。前者由模型状态变更驱动，后者由图片加载任务驱动；`body` 求值、滚动、切换主题和布局变化都不得写来源锁或发起新的背景请求。

## 3. 图层顺序与模糊职责

| 从后向前 | 氛围版式（iPhone / iPad 窄窗） | 翻页版式（macOS / iPad 宽窗） |
| --- | --- | --- |
| 底色 | `Color.pageBackground` | 同左 |
| 进页过渡 | 固定池图 + `.home` 模糊/雾化 | 同左，仅模糊，不显示另一作品的清晰图 |
| 条目图组 | 同一条目快照 + `.detail` 模糊/渐变 | 同一快照的清晰层 + 同像素模糊层 + 遮罩 |
| 前景 | 固定高度标题、元数据、正文 | 第一页标题/操作，第二页正文；前景各自避让系统栏 |
| 系统浮层 | 导航栏、底栏、弹窗材质 | 导航栏、弹窗材质 |

`BackdropAmbienceView` 负责氛围视觉：日间 blur 20、夜间 blur 14，放大 1.12 倍消除虚边，使用已有 `.home` / `.detail` 雾化渐变。首页的均衡雾化与详情底部归于页面底色的渐变有不同目的，保留两种档位。

`DetailPageArt` 负责翻页视觉：清晰图铺满视口，模糊层使用同一份图片，blur 30、放大 1.15 倍、saturation 1.02，并加自适应白雾/黑纱。第一页左侧实体遮罩为 0.34 倍视口宽，接 0.34 倍宽渐隐；第二页将实体遮罩扩张到 1.75 倍宽。翻页只改变遮罩和前景，不重新加载图片，也不切换到独立的小图。

两种版式在 `DetailBackdropView` 内作为完整图组交叉淡入，不允许清晰层和模糊层各自淡入。正文不重复加全页底图。卡片、胶囊按钮的材质只服务局部可读性，不能用多叠一层全屏模糊来解决文字对比。

## 4. 图片预算与维护约束

- 首页池维持 800 宽 URL / 512 像素解码。详情最终图维持 1600 宽 URL / 1920 像素解码；不因为模糊另取 800 宽版本。点击预取和详情加载使用相同来源策略与缓存键。
- 一次详情访问最多持有一张过渡小图和一张最终图片；两种视觉层共用最终图片对象。原图与项目图片资产不作破坏性处理。
- 禁止在 `DetailView` 新增绕过快照的背景 `RemoteImage` 或直接读取实时 `currentAmbienceTarget`。海报、Logo、演员等前景图片仍有各自加载职责。
- 新版式先复用 `DetailBackdropView`，新增来源先修改共享解析，再修改来源锁与测试，不能在某个视觉层临时加来源兜底。
- 灰度采样只能证明背景覆盖，不能证明清晰图与模糊图同源；来源探针记录已提交的像素来源，仍须结合转场截图或录屏核对视觉结果。

## 5. 验证范围

自动测试 `DetailBackdropArtworkTests` 覆盖进页快照冻结、缓存淘汰、无缓存、解码前后提交、重复准备、失败、迟到取消结果、已取消调用方不能重启加载以及退出后重新准备。来源锁、认证、合集、点击预取、取消加载、路由覆盖与翻页状态沿用相关测试。

视觉复核需包含：首页轮播即将切换时进页；缓存命中与首次加载；无图/失败；详情 A → B → 返回；第一页加载中翻到正文；明暗主题；降低动态效果；iPhone 竖/横屏；iPad 宽/窄窗；macOS 调整窗口。判据是清晰与模糊始终同源、一次访问最多一次条目图切换、无错图清晰帧、头部不因图片到达重排、边缘不漏色且图片不覆盖侧栏。
