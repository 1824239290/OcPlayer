# 弹幕渲染开关保存修复（2026-11-19）

用户在设置页关闭“用内核渲染弹幕”后，返回再进入时仍看到开启。原因是
`DanmakuSettingsEditor.Read()` 能读取开关状态，但设置页只在点击下方的
“保存弹幕设置”按钮时调用它。开关切换没有保存事件，退出页面后重新读取旧配置。
现有 PasswordVault 写入可以更新同一份凭据，本轮保留原有存储实现。

设置页调用 `EnableToggleAutoSave`，将自动加载、显示、渲染路线和过滤等开关的
切换直接保存到现有设置。每次只修改对应字段，使用最新保存配置作为基准，避免
未完成的网关或其他输入阻止切换、或被意外提交。保存失败会恢复开关并显示原因。
播放器弹窗不启用自动保存，继续使用“保存/取消”；渲染路线仍从下次播放生效。

最终 x64 Debug、集成项目、Release 构建均为 0 警告、0 错误。完整集成回归
414 条断言通过，包含使用真实 Windows 凭据存储反复关闭/开启/关闭后重新读取。
真实 WinUI 回归 36 条断言通过，新增检查覆盖：

- 不点击保存按钮时，设置页开关直接保存。
- 离开再返回页面，开关保留。
- 开关保存不提交未完成的网关输入。
- 反复切换后重建页面和重新读取凭据仍保留选择。
- 写入失败回退开关并显示原因。
- 播放器弹窗的开关仍等待显式保存。

Release 启动检查通过，所有最终验证进程退出码均为 0。真实 Release 窗口中
关闭开关后显示“弹幕设置已保存”，返回该页仍为关闭。当前窗口保持应用层路线。
